# 3D タワーディフェンス

ローポリ 3D のタワーディフェンス。ポートフォリオ用のソロ開発作品です。

## ゲーム概要

敵が決まったルートを進んで拠点のクリスタルを狙ってきます。プレイヤーは設置可能マスにタワーを置き、
自動攻撃で敵を食い止めます。撃破で得たゴールドで次のタワーを買い、全 8 ウェーブを守りきれば勝利、
ライフが 0 になれば敗北です。

## 遊び方

**操作**

| 操作 | 動作 |
| --- | --- |
| 画面下のボタン | 建てるタワーを選ぶ |
| 左クリック（設置可能マス） | 選んだタワーを建てる |
| 右クリック / Esc | 選択を解除 |
| 「次の波へ」ボタン（右上） | 待ち時間を飛ばして次の波を呼ぶ |
| 左クリック（建てたタワー） | カメラが寄って砲台を間近で見る |
| もう一度クリック / 右クリック / Esc | 引きの画面に戻る |

**タワー設置**

マップ上には設置可能マスが 10 か所あります。タワーを選ぶとマスの色が変わり、
**緑なら設置可能・赤ならゴールド不足**です。1 マスに 1 本まで、建て替えはできません。

| タワー | コスト | 火力 | 特徴 |
| --- | --- | --- | --- |
| アロータワー | 50 G | 4 × 1.6 発/秒 | 単体攻撃。安く、連射がわずかに速い |
| フロストタワー | 55 G | 4 × 1.5 発/秒 | 命中した敵を減速（速度 35%・2.5 秒） |

火力はほぼ同じで、減速が付くぶん少し高い・少し遅い、という関係です。
どちらか一方に寄せるより**混ぜたほうが強く**、通常砲だけでは 8 波目を越えられません。

**ゴールド**

開始時に 120 G。敵を倒すとゴールドが入り（通常 9 G / 高速 13 G）、買えないタワーのボタンは
自動的に押せなくなります。**2〜3 本では最後まで持たない**難度なので、稼いだぶんを継ぎ足しながら
守りを広げていくのが基本です。

**ウェーブ**

全 8 波。波が進むほど敵の数が増え、出現間隔も短くなります。
波と波の間には準備時間があり、**右上の「次の波へ」で待たずに呼べます**
（呼ばなくても時間で始まるので、放置してもゲームは止まりません）。**4 波目からは高速敵が混ざり**、
通常敵の列に割り込んで走ってきます。1 つの波を殲滅すると数秒後に次の波が始まります。

| 敵 | HP | 速度 | 到達時のライフ減少 |
| --- | --- | --- | --- |
| 通常（スライム） | 25 | 2.4 | 1 |
| 高速 | 16 | 4.8 | **3** |

**勝敗条件**

- **勝利**: 8 波すべてを殲滅する
- **敗北**: ライフ 20 が 0 になる（高速敵の取りこぼしは 1 体で 3 減るので致命的）

決着すると画面が止まり、そのままリスタートできます。

## 技術ポイント

**Resource によるデータ駆動設計**

敵・タワー・ウェーブのステータスをコードに書かず、すべて `Resource` に分離しています
（[scripts/data/](scripts/data/) と [resources/](resources/)）。

- `EnemyData` … HP / 速度 / 撃破報酬 / 到達ダメージ / 色 / スケール
- `TowerData` … コスト / 火力 / 射程 / 連射 / 追加効果 / 専用シーン
- `WaveData` + `WaveEntry` … 各波の「敵種 × 数 × 出現間隔 × 開始遅延」

この分離のおかげで、**種類追加やバランス調整がコード変更なしで完結**します。実際に敵とタワーの
2 種類目は `.tres` を 1 つ足すだけ、バランス調整は数値の書き換えだけで済んでいます。
UI のタワー選択ボタンも `TowerData` の配列から生成しているので、タワーを増やしても UI は変更不要です。

**ターゲット選択ロジック**

タワーは射程内で**最もゴールに近い敵**（`progress_ratio` が最大の敵）を狙います
（[scripts/tower.gd](scripts/tower.gd)）。一番近い敵を狙う実装より取りこぼしが減るためで、
ルート上の進行度をそのまま優先度に使えるのが `PathFollow3D` を採用した副産物になっています。

**Path3D / PathFollow3D による経路**

敵は `Path3D` の子として生成した `PathFollow3D` で、`progress` を毎フレーム進めるだけで移動します
（[scripts/enemy.gd](scripts/enemy.gd)）。固定ルートと割り切ることで経路探索を持たず、
「進行度」という 1 次元の値で位置・ターゲット優先度・ゴール判定をすべて表現しています。

**シグナルによる疎結合**

状態は Autoload の `GameState` 1 か所に集約し、変化は signal で流します
（[scripts/game_state.gd](scripts/game_state.gd)）。UI やマネージャは購読するだけで、
状態を書き換えに来ません。

- `gold_changed` / `lives_changed` / `wave_changed` / `game_over` / `game_won`
- 敵は `died(gold_value)` / `reached_end(damage)` を出すだけで、ゴールドやライフを直接触らない
- ゴールドの支払いは必ず `spend_gold()` を通し、**戻り値が false ならタワー生成に入らない**ので
  「払えていないのに建つ」が構造的に起きない

**WaveManager**

波の進行を `await` で手続きとして直接書いています（[scripts/wave_manager.gd](scripts/wave_manager.gd)）。

```gdscript
await _spawn_wave(wave)            # 湧き切るまで待つ
await _wait_until_field_cleared()  # 全滅するまで待つ
await _wait(wave.next_wave_delay)  # 次の波まで待つ
```

状態機械を持たずに読める形で流れが表現できます。1 波に含まれる `WaveEntry` は並行に走るので、
`start_delay` をずらすだけで敵種を混ぜられます。待ち時間は `SceneTree` のタイマーではなく
**子ノードの `Timer`** で計っており、ポーズ中は待ちも止まり、リスタート時に解放済みインスタンスを
再開してしまう事故も起きません。

**ステージの手続き生成**

地形・道・拠点クリスタル・岩や木は、モデルを読み込むのではなく起動時にコードで組み立てています。

- [scripts/terrain.gd](scripts/terrain.gd) … 高台・崖・低地・遠景の山を生成。
  **道と設置マスの周りだけ起伏を平らに均す**ので、y=0 前提で置かれた道やタワーが浮かない。
  格子は中心ほど細かく外ほど粗い可変間隔にして、面数を抑えたまま 150 単位先まで作る
- [scripts/road_visual.gd](scripts/road_visual.gd) … `Curve3D` の断面をつないだリボン。
  幅を左右で別々に揺らし、地形の高さに乗せて土の道に見せる
- [scripts/prop_scatter.gd](scripts/prop_scatter.gd) … 岩・茂み・木を `MultiMesh` でばら撒く
  （道・設置マス・拠点を避ける判定つき、ドローコールは種類ごとに 1 回）
- [scripts/low_poly.gd](scripts/low_poly.gd) … 塊メッシュを作る共通処理。岩・茂み・敵で共有

いずれも**面ごとの法線（フラットシェーディング）＋頂点カラー**で、画像テクスチャもカスタム
シェーダーも使っていません。GL Compatibility レンダラと Web 書き出しで素直に動くことを優先し、
陰影はライティング側（逆光寄りのキーライト＋寒色のフィルライト＋フォグ）で作っています。

遠近感も同じ制約の中で作っています。Compatibility レンダラは深度フォグを無視して指数フォグ
しか効かず、遠景が霞むまで濃くすると遊ぶ高台まで白くなってしまいます。そこで**空気遠近は
地形の頂点カラーに焼き込み**、`Environment` のフォグは木や岩に掛かるぶんだけ薄く残しています。

**タワーをクリックして寄るカメラ**

見下ろし固定のカメラに、建てたタワーへ寄る動きだけを足しています
（[scripts/camera_rig.gd](scripts/camera_rig.gd)）。

- カメラは向きを `Transform3D` で持たず「どこを見るか」だけを持ち、向きは位置から毎回計算する
- 寄りの視点は固定オフセットではなく、**引きの視点と同じ方位から角度だけ下げて**求める。
  マップのどちら側のタワーでも見え方が揃う
- 位置と注視点は 1 本の値（0→1）で同時に補間する。別々に補間すると、
  途中で視線だけ先に着いて不自然な振り向きになる
- タワーの当たり判定はシーンではなく `Tower._ready()` で足している。タワーのシーンは
  3 つあるので、形と大きさを 1 か所で決められるほうが崩れない
- 埋まった設置マスのクリックは `BuildManager` が握り潰さないようにして、カメラ側へ渡している

**画面を見ずに検証できるツール**

3D の見た目に依存しない部分を CI 的に確認できるようにしてあります。

- [tools/headless_check.gd](tools/headless_check.gd) … シーン構成・UI ボタン・購入・撃破・減速の通し確認
- [tools/balance_sim.gd](tools/balance_sim.gd) … 8 波を早送りで通しプレイし、勝敗とライフ残量を出力
- [tools/export_tower_models.py](tools/export_tower_models.py) … Blender から glTF への書き出しを再現
- [tools/vis_preview.tscn](tools/vis_preview.tscn) … 見た目確認用。タワーを数本建てた状態を作る。
  Godot の Movie Maker モード（`--write-movie <出力先>/f.png`）と組み合わせると PNG で残せる。
  末尾に `-- focus` / `-- wave` / `-- fx` を付けると、寄りのカメラ・ウェーブ開始ボタン・
  エフェクトをそれぞれ確かめられる
- [tools/make_sfx.py](tools/make_sfx.py) … 効果音 9 種を合成して `assets/audio/` へ書き出す

バランス調整は `balance_sim.gd` の結果を見ながら決めています（基準値は [docs/GDD.md](docs/GDD.md) 参照）。

## 使用技術

- **エンジン**: Godot 4.6（GDScript / GL Compatibility レンダラ）
- **3D モデル**: Blender で作成し、glTF (`.glb`) で書き出して取り込み
- **物理**: Jolt Physics（射程判定と設置マスのレイキャストに `Area3D` を使用）
- **効果音**: 暫定。標準ライブラリだけの Python スクリプトで合成している
  （[tools/make_sfx.py](tools/make_sfx.py)）。外部素材への差し替え予定

## 起動方法

Godot 4.6 以降が必要です。

1. Godot を起動し、プロジェクトマネージャから `project.godot` をインポートして開く
2. エディタで **F5** を押す（メインシーンは `scenes/main.tscn`）

コマンドラインから直接実行する場合:

```bash
godot --path .
```

**確認用ツールの実行**

```bash
godot --headless --path . --script tools/headless_check.gd
```

```bash
godot --headless --path . --script tools/balance_sim.gd -- --towers 3
```

`--towers` は建てるタワーの上限です。`3` なら「3 本しか建てない下手なプレイヤー」、
`99` なら「置けるだけ置く上手なプレイヤー」を模擬できます。

**モデルの再書き出し**

```bash
blender -b tower_basic.blend --python tools/export_tower_models.py -- assets/models TowerBasic tower_basic
```
